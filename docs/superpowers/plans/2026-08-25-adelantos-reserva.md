# Adelantos de reserva Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let staff register that a client advanced money today for a reservation on a future date/time; that reservation blocks the court, is permanently marked and rendered black on the grid, and shows up in a "pending adelantos" list until fully paid.

**Architecture:** Reuses the existing `Reserva` + `Pago` models (no new tables). A new `Reserva.es_adelanto` boolean flag, set only at creation time through a new frontend dialog, drives both the permanent black grid styling and a new "pending adelantos" backend endpoint. `POST /api/reservas/` already accepts an arbitrary future `fecha`, so the only backend change is the new flag plus threading it through the existing payment-saving path.

**Tech Stack:** Django REST Framework (backend), React + Tailwind/shadcn (frontend), Django's test runner (`python manage.py test`), no frontend automated test suite (manual browser verification).

**Spec:** `docs/superpowers/specs/2026-08-25-adelantos-reserva-design.md`

## Global Constraints

- Backend tests run from `backend/` with `python manage.py test reservas` (or a dotted path to one class/method). No pytest config exists — use Django's runner.
- There is no frontend automated test suite (`frontend/package.json` has no `test` script). Frontend tasks are verified by running `npm run build` (catches import/syntax errors) plus a manual check in the browser; the final task does a full manual end-to-end pass.
- Match existing code style: Spanish identifiers, comments only where they explain a non-obvious *why* (see existing files for tone), snake_case in Python, the project's existing Tailwind class patterns in JSX.
- `es_adelanto` is never toggled after creation (spec 2.2/6) — no task should add an update path for it.
- The "Agregar adelanto" flow never offers an academia selector (spec 2.5) — do not add one.

```python
def guardar_pago(reserva, metodo, monto, usuario, tipo=Pago.Tipo.SALDO):
    """Upsert de a lo sumo un Pago por (reserva, metodo). monto<=0 borra el
    pago existente (equivale a 'no pago por este metodo'). Si hubiera mas
    de un Pago legacy del mismo metodo (dato de antes de este cambio),
    actualiza el mas reciente y deja los demas intactos. 'tipo' solo se usa
    al CREAR el pago (ej. ADELANTO desde el flujo de adelantos); un pago
    que se actualiza despues de creado siempre queda en SALDO -- ya no es
    "el adelanto inicial", es el pago que completa (o corrige) lo que
    falta."""
    pago = reserva.pagos.filter(metodo=metodo).order_by('-fecha_hora').first()
    if monto <= 0:
        if pago:
            pago.delete()
        return None
    if pago:
        pago.monto = monto
        pago.tipo = Pago.Tipo.SALDO
        pago.registrado_por = usuario
        pago.save(update_fields=['monto', 'tipo', 'registrado_por'])
        return pago
    return Pago.objects.create(
        reserva=reserva, metodo=metodo, monto=monto, tipo=tipo,
        registrado_por=usuario,
    )
```

```python
def listar_adelantos_pendientes():
    """Reservas marcadas como adelanto que todavia tienen saldo por cobrar
    (precio_total > suma de sus pagos), sin cancelar, ordenadas por fecha y
    hora ascendente. No se filtra por fecha a proposito -- ver spec de
    adelantos seccion 2.4 -- para no perder de vista un adelanto viejo que
    quedo sin completar."""
    candidatas = (
        Reserva.objects.filter(es_adelanto=True)
        .exclude(estado=Reserva.Estado.CANCELADA)
        .prefetch_related('pagos')
        .order_by('fecha', 'hora_inicio')
    )
    resultado = []
    for reserva in candidatas:
        pagado = sum((p.monto for p in reserva.pagos.all()), Decimal('0.00'))
        if pagado < reserva.precio_total:
            resultado.append(reserva)
    return resultado
```

```js
export const OPCIONES_DURACION = [1, 1.5]

export function etiquetaDuracion(horas) {
  const enteras = Math.floor(horas)
  return horas % 1 === 0.5 ? `${enteras}h 30min` : `${enteras}h`
}

export function calcularHoraFin(horaInicio, duracionHoras) {
  const [h, m] = horaInicio.split(':').map(Number)
  const totalMin = (h * 60 + m + duracionHoras * 60) % (24 * 60)
  const hh = Math.floor(totalMin / 60)
  const mm = totalMin % 60
  return `${String(hh).padStart(2, '0')}:${String(mm).padStart(2, '0')}`
}
```
